Project S-7 (Working Title) — Updated Notes

2D пиксельная RPG с видом сверху, вдохновлённая классикой уровня Shining Force 2. Проект строится вокруг перемещения по сетке, взаимодействия с объектами и модульной архитектуры (диалоги, двери, UI, инвентарь/экипировка).
Цель — сделать чистую и расширяемую систему без лишней сложности на раннем этапе, при этом по максимуму выводить настройки в Inspector.
Core Systems (Implemented) — текущий статус
•	Movement (tile-based): сетка 32×32, пошаговое движение, удержание — непрерывное, поворот на месте; блокировки: слой непроходимых тайлов, NPC, закрытые двери.
•	Interaction system: взаимодействие только с объектом перед персонажем с учётом направления; интерактивная зона впереди; объект сам решает свою логику.
•	Dialogue system: диалог с NPC, пролистывание кнопкой действия; во время диалога движение/поворот отключены.
•	Door system: дверь открыта/закрыта, меняет вид и коллизию; закрытая блокирует проход; за дверью — переход в локацию.
•	Interaction architecture: единый принцип (игрок инициирует, объект выполняет) — NPC/двери/будущие объекты.
UI & Menu (In Progress) — что уже сделано и проверено
•	Крест-меню (MenuRoot) вызывается отдельной кнопкой и не ставит игру на паузу, но блокирует движение игрока.
•	Инвентарь (InventoryScreen) открывается из крест-меню и управляется только клавишами (WASD + E, без мыши).
•	Сетка инвентаря: 8×4 видимая область, поддержка выделения слотов (подсветка), скролл для списка предметов.
•	Preview/описание справа: при смене выделения слот → обновляется превью и текст описания.
•	ItemData как Resource (.tres): icon (32×32), preview (128×128), title, description, pickup_color.
•	Секретка (SecretWall): интерактивный объект в мире, вызывает диалог и добавляет предмет в инвентарь.
•	Диалог переведён на RichTextLabel с bbcode для раскраски текста в сообщениях (например, цвет названия предмета).
Data Model — предметы, слоты и совместимость (Inspector-driven)
Мы разделяем два разных понятия: (1) вкладки инвентаря (категории) и (2) слот экипировки. Категория используется для фильтра/вкладок, а слот — для того, куда предмет можно надеть.
•	ItemData (Resource) содержит:
•	item_class: WPN / ARM / POT / OTH — категория для вкладок инвентаря.
•	equip_slot: NONE / HEAD / ARMOR / BOOTS / WEAPON / RING — куда надевается предмет.
•	required_profs_mask (flags): AXE, SWORD, MACE, BOW, STAFF, DAGGER, ROBE, LIGHT_ARMOR, HEAVY_ARMOR — требования к владениям/допускам. 0 = без ограничений.
•	HeroData (Resource) планируется/вводится для героев:
•	hero_name, profession_name (для отображения в UI).
•	allowed_profs_mask (flags) — что умеет герой. Используется для фильтра предметов при экипировке.
Equipment (Equip вкладка) — подробный план и текущее направление
•	Цель интерфейса Equip:
•	Верхняя панель PartyBar: портреты 7–8 героев. Навигация влево/вправо (A/D).
•	После выбора героя (E) фокус переходит на EquipSlots (крест из 5 слотов): Head, Armor, Boots, Weapon, Ring.
•	Навигация по слотам — фиксированная логика (как крестик): W/S по центральной колонке (Head→Armor→Boots), A уходит на Weapon, D уходит на Ring, A/D возвращают назад в колонку.
•	Tab — шаг назад: из слотов обратно к выбору героя; из выбора героя — выход обратно в крест-меню.
•	Как будет происходить выбор конкретного предмета (вариант A — переиспользуем инвентарь):
•	Нажатие E на конкретном слоте в EquipSlots открывает InventoryScreen в режиме 'equip selection'.
•	InventoryScreen фильтрует предметы по двум условиям: item.equip_slot == выбранный слот и (hero.allowed_profs_mask & item.required_profs_mask) != 0 (или required_profs_mask == 0).
•	Игрок выбирает предмет в сетке инвентаря WASD и подтверждает E. Инвентарь эмитит сигнал equip_item_selected(item).
•	EquipScreen принимает item и отображает его (preview/icon) в соответствующем слоте; предмет убирается из инвентаря (позже можно сделать swap/возврат старого предмета).
•	Tab в режиме выбора отменяет и возвращает в EquipScreen без изменений.
•	Что будет добавлено после базовой версии:
•	Хранение экипировки отдельно по каждому герою (слоты → ItemData).
•	Снятие предмета (Unequip) и возврат в инвентарь; замена предмета (swap).
•	Бонусы к характеристикам от экипировки (StatsPanel).
•	Ограничения по уровню/статам (required level/str/int) поверх allowed_profs_mask.
Важные примечания (чтобы не ломалось)
•	Структура сцены и имена нод критичны: многие ссылки идут по путям или по группам.
•	Для поиска инвентаря/экранов удобно использовать Groups (например, inventory_screen).
•	Всегда следить за табами/пробелами в GDScript: смешивание вызывает ошибки компиляции.
•	Мышь в UI лучше отключать настройками Input/Mouse и не полагаться на hover-состояния.
